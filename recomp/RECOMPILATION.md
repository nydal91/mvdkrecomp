# Recompilation Guide: Switch $\rightarrow$ Android

This directory is prepared for a static recompilation workflow using **DeepSeek Flash 4.1**.

## 🚀 Quick Start

### 1. Assets (ROMFS)
The game's assets are in `romfs/`. Many files use `.zs` compression (e.g., `.byml.zs`).

1.  **Decompress Assets:** You must decompress `.zs` files first.
2.  **Input:** Place the decompressed content into `recompilation/inputs/decompressed_assets/`.
3.  **Translate:** Use the `recompilation/prompts/templates.md` file to prompt DeepSeek to convert these assets (like `.byml`) into JSON or C++ headers.
4.  **Save:** Store DeepSeek's output in `recompilation/outputs/assets/`.

### 2. Logic (EXEFS)
The main game logic is in `exefs/main` (Nintendo Switch NSO format).

1.  **Disassemble:** Use a Nintendo Switch-compatible disassembler (like `ghidra` with Switch plugins) to extract ARM64 assembly.
2.  **Input:** Save the assembly output as `.asm` in `recompilation/inputs/assembly/`.
3.  **Decompile:** Use the **Function Decompilation** template in `recompilation/prompts/templates.md` to ask DeepSeek to convert the assembly into C++.
4.  **Save:** Store the resulting C++ code in `recompilation/outputs/logic/`.

## 📂 Directory Map
- `recompilation/inputs/`: Raw data for DeepSeek.
- `recompilation/outputs/`: Cleaned code/assets generated by DeepSeek.
- `recompilation/prompts/`: Instruction templates for the LLM.
- `recompilation/scripts/`: Helper scripts.

---
*Note: This setup is optimized for DeepSeek Flash 4.1's strengths in code translation and pattern recognition.*
